# ADR-0113 — A bot pushing onto a pull request replays its commit past another bot

**Status:** Accepted. Amends
[ADR-0106](ADR-0106-every-line-of-the-matrix-derives-from-one-source-item.md)
point 4, and through it
[ADR-0101](ADR-0101-ci-regenerates-the-traceability-matrix.md), on what a
rejected push means. Amends
[ADR-0057](ADR-0057-same-repo-pull-requests-translate-in-pr.md) on how the
French is pushed onto a same-repo pull request. Both bots still commit onto
the pull request's own branch, and neither ever pushes to `main`.

## Context

On PR #392, one push (60e0f25) changed both a feature file and
`locales/en-CA.json`, so it started both `traceability.yml` and
`i18n-translate.yml`. The translation bot pushed first (b863066). The
traceability bot's push was rejected (`! [rejected] … (fetch first)`), and
the required `docs` check stayed red until the matrix was regenerated by hand.

ADR-0106 said a push rejected by a moved branch is superseded, because the
push that moved it "starts its own run over the newer head." That holds for
an author's push. It does not hold for a bot's. GitHub evaluates a
`pull_request_target` workflow's `paths` against what each push changed.
b863066 changed only `locales/fr-CA*.json`, which neither workflow is
triggered by, so it started CI and nothing else. No run of
`traceability.yml` existed to regenerate over it. Under ADR-0106's handler,
which merged after #392, the same race would have exited green while `docs`
stayed red.

The race runs both ways. If the traceability bot wins, the translation bot's
push fails, and the matrix commit does not touch `locales/en-CA.json`, so no
later run translates.

## Decision

Both bots push through `tools/push-to-pr-branch.mjs`. When a push is
rejected, the tool fetches the branch and lists the files it gained since the
event's head SHA:

1. **The branch did not move.** The push failed for a real reason. The job
   fails.
2. **A file the workflow is triggered by changed.** That push started its own
   run of this workflow over the newer head. This run is superseded: it emits
   a notice and exits 0, as ADR-0106 said.
3. **Only other files changed.** Nothing else will redo this run's work. The
   files that changed are not this workflow's inputs, so its output is still
   correct over the newer head. The tool cherry-picks its commit on top and
   pushes again, up to five times. A commit that does not apply fails the job.

Each workflow passes its own `pull_request_target.paths` to the tool.
`tests/js/push-to-pr-branch.test.mjs` fails when the two lists disagree, and
it drives every outcome against real repositories.

`traceability.yml` runs the base branch's copy of the tool, as it already
does the generator. `i18n-translate.yml` runs the copy in its own checkout,
as it already does the translator.

## Alternatives considered

- **One `concurrency` group for both bots per pull request.** The runs would
  take turns, but the second still checks out the event's pinned head SHA,
  commits on top of it, and is rejected the same way.
- **Drop the `paths` filter from `traceability.yml`**, so every push runs it.
  That fixes the matrix side only. The translation side still loses, and
  running the translator on every push costs provider calls.
- **Retry by regenerating over the newest head.** Correct for the matrix,
  but for the translation it spends a provider call, and neither is needed:
  a push that changed none of a workflow's inputs cannot change its output.

## Consequences

- A bot commit that loses the race lands on top of the winner, and the
  `docs` and i18n checks re-run on the combined head.
- A future workflow that commits onto a pull request's branch pushes through
  the same tool, never a bare `git push`
  ([`deliver-hpac-change`](../../skills/deliver-hpac-change/SKILL.md)).
- A `paths` pattern the tool does not understand throws rather than matching
  nothing. Today the workflows use only `dir/**` and exact paths.
- This pull request changes `traceability.yml`, which `pull_request_target`
  runs from the base branch, so its first live proof is the next pull request
  that changes a feature file and `locales/en-CA.json` together.
