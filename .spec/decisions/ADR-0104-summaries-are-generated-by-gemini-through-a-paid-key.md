# ADR-0104 — Summaries are generated by Gemini through a paid key

**Status:** Accepted. Its provider mechanism is amended by
[ADR-0179](ADR-0179-gemini-translates-everything-between-canadian-english-and-canadian-french.md): an `IAiMediator` with one handler per
provider, picked by the model's name, replaces the `Provider` setting and the
strategy map, and the summary is one of two callers (`OpenAiSummarizer`; the
other is `OpenAiTranslator`). The summary's behavior, key, model, reasoning
level, and boundary below stand. Amends
[ADR-0009](ADR-0009-hosting-on-aws.md) (`ca-central-1` residency) and
[ADR-0038](ADR-0038-question-privacy-and-llm-anonymization.md) (provider terms)
for the one summarization boundary, and narrows CON-INF-005 in
[infrastructure and operations](../infrastructure-and-operations.md). Replaces
the Anthropic provider that [ADR-0007](ADR-0007-localization.md) and
[ADR-0022](ADR-0022-translation-provider-is-configuration.md) assumed.

## Context

The Worker already makes the one summarization call
([ADR-0082](ADR-0082-a-deterministic-marking-pass-precedes-the-one-model-call.md))
through `IAiMediator`, and a `GeminiHandler` already existed, but nothing
recorded the choice of provider:

- no model was configured anywhere, so every call named an empty model;
- ADR-0007 and ADR-0022 still described an Anthropic client;
- ADR-0009 keeps every service that touches report data in `ca-central-1`, and
  ADR-0038 requires provider terms, retention, and residency to permit the model
  to read both `report_content` and `private_context`;
- CON-INF-005 keeps every secret value in Secrets Manager, while the deploy
  workflow already planned the Gemini key as a GitHub repository secret.

The owner wants a cheap model, a configuration file in the Worker that names
it, and a key that comes from GitHub, and wants a later switch to Claude,
ChatGPT, or another provider to be a new class rather than a rewrite.

## Decision

**Gemini is the summarization provider.** The Worker calls Google's Gemini API
through its OpenAI-compatible chat-completions endpoint.

**One configuration section holds the key, model, and reasoning level
together.** The Worker's `appsettings.json` carries, with no provider setting:

```jsonc
"AiChatClient": {
  "ApiKey": "",               // never committed; see below
  "Model": "gemini-3.7-flash",
  "ReasoningEffort": "low"    // low | medium | high
}
```

**The model name picks the provider.** `IAiMediator` takes one OpenAI-style
request (model, messages, and optionally a reasoning level and a response
format) and hands it to the `IAiHandler` whose model-name prefix matches the
model. The mediator is the only place that tells providers apart. The one
handler today is `GeminiHandler`, which claims `gemini-*` and calls Gemini's
OpenAI-compatible endpoint with the Gemini key (`AiChatClient:Endpoint`
overrides it). The summary asks for a JSON object at the configured reasoning
level. With no key, the mediator reports itself unconfigured and every call
fails closed. With a key, a model no handler claims, a blank model, or a
reasoning level other than `low`, `medium`, or `high` stops the Worker at
startup.

**The reasoning level is `low` and the temperature is left at its default.**
Summarizing one report under explicit rules is rule-following, not open-ended
reasoning: the marking pass already replaces exact private values before the
call, and the prompt carries a complete English/French replacement table,
forbidden wording, accuracy rules, and a worked example. Gemini 3 Flash
defaults to `high` thinking, which is billed. Google recommends leaving Gemini
3's temperature at its default of 1.0 and warns that lowering it can cause
looping, so no temperature is sent. If reviewers find paraphrased identities
getting through, the reasoning level is raised in configuration.

**A paid, billing-enabled key is used in every environment.** Google's free
tier may use submitted content to improve its products. Reports carry names,
contact details, and injuries, so no environment uses a free-tier key, and
development runs on synthetic data.

**Only a consented report crosses.** A report whose reporter did not consent
to publication is never summarized, so it is never sent to Google (amended
2026-09-23, REQ-DOM-006, REQ-AI-027).

**Processing outside Canada is accepted for this one boundary.** The Gemini API
offers no Canadian-region guarantee. The owner accepts that `report_content`
(after marking) and `private_context` are processed by Google for the one call
per attempt. Nothing else crosses: documents, attachments, filenames, consent,
and deleted content never reach the model (REQ-AI-009, REQ-AI-016). The
database, bucket, and every other service stay in `ca-central-1`.

**The key comes from a GitHub repository secret.** `GEMINI_API_KEY_PROD` is
passed to the Worker task as `AiChatClient__ApiKey`, and `GEMINI_API_KEY_DEV`
is exported locally as `GEMINI_API_KEY`, which docker-compose maps to the same
setting. This is the second exception to CON-INF-005, alongside DeepL's key: it
is the Worker's only external credential, and copying it into Secrets Manager
buys nothing an operator cannot already get from GitHub's secret store. The key
is never committed, logged, or returned in an error.

## Considered options

- **Vertex AI in `northamerica-northeast1`.** Keeps processing in Canada, but
  needs Google Cloud service-account authentication and a second client shape.
  Not worth it for the volume this system handles, given the owner accepts the
  transfer.
- **A free-tier key for development.** Cheaper, but the same code path would
  send data under terms that allow Google to use it; one rule for every
  environment is simpler to keep.
- **An explicit `Provider` setting.** This ADR first chose it over selecting
  the provider from the model name's prefix, because it does not depend on
  naming conventions a provider controls. The owner reversed that
  (2026-09-30, [ADR-0179](ADR-0179-gemini-translates-everything-between-canadian-english-and-canadian-french.md)): translation and the summary
  each name their own model over one key, so the model is the one thing that
  must be stated, and a second setting that could disagree with it is removed.
- **A deterministic output check for leaked names or the word "redacted".**
  Rejected by the owner; the reviewer owns the final privacy decision
  ([ADR-0004](ADR-0004-human-review-required.md)).
- **Temperature 0 for determinism.** Contrary to Google's guidance for Gemini 3.

## Consequences

- A summary row's `model` is `gemini-3.7-flash` and its `prompt_version` names
  the prompt that produced it.
- Switching to Claude, ChatGPT, or another provider is one new `IAiHandler`
  class claiming its models' prefix, one registration line, a configuration
  change, and a new ADR covering that provider's terms and residency.
- Changing the model or reasoning level is a configuration change; the value is
  stamped on every summary it produces.
- The deploy workflow injects the key once the Worker service roll exists
  (#30); until then production summarization fails closed.
